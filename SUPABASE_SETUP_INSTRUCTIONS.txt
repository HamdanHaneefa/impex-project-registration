SUPABASE SETUP - Quick Instructions
====================================

STEP 1: Create Table in Supabase
---------------------------------
1. Go to https://supabase.com/dashboard
2. Select your project: iikjmeiitqskktdnxpcd
3. Click "SQL Editor" in left sidebar
4. Click "New query"
5. Copy ALL content from "supabase-setup.sql" file
6. Paste into SQL editor
7. Click "Run" button
8. You should see: "Success. No rows returned"

STEP 2: Verify Table Created
-----------------------------
1. Click "Table Editor" in left sidebar
2. You should see "registrations" table
3. Click on it to see columns:
   - id
   - full_name
   - phone
   - email
   - designation
   - institute
   - attendees
   - food_preference
   - created_at

STEP 3: Test the System
------------------------
1. Make sure dev server is running: npm run dev
2. Fill out registration form
3. Submit form
4. Check BOTH:
   - Google Sheets (should have new row)
   - Supabase Table Editor (should have new row)

STEP 4: Monitor Submissions
----------------------------
To view registrations in Supabase:
1. Go to Table Editor
2. Click "registrations" table
3. See all submissions with timestamps

HOW IT WORKS
============
- Form submits to BOTH Google Sheets AND Supabase
- If Google Sheets fails, Supabase still saves (backup!)
- If Supabase fails, Google Sheets still saves (primary!)
- Only fails if BOTH fail
- User never sees "Supabase" mentioned in error messages

TROUBLESHOOTING
===============
If submissions not appearing in Supabase:
1. Check browser console for errors
2. Verify .env has correct VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
3. Verify table was created (check Table Editor)
4. Check RLS policies are enabled
5. Restart dev server after any .env changes

SECURITY
========
- Supabase credentials are in .env (not committed to git)
- RLS (Row Level Security) is enabled
- Public can INSERT (submit forms)
- Only authenticated users can SELECT (view data)
- Your anon key is safe to use in frontend
